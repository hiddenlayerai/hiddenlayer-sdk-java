# Breaking API Changes: v2.x → v3.0.0

v3.0.0 is generated by [Fern](https://buildwithfern.com/) from the same OpenAPI specification that generated v2.x with Stainless. The Maven coordinate `com.hiddenlayer.api:hiddenlayer-java`, Java 8 support, the `HIDDENLAYER_*` environment variables and the model and community scanners all stay. Every method v2.5.0 had keeps its name and its place on the client; what changes is how a client is built, the packages and names of the request and response types, how arguments are passed, errors, and two methods that now paginate. v3.0.0 also adds every API in the specification that v2.x didn't cover.

v2.5.0 was tagged but never reached Maven Central, so an upgrade from Maven Central's latest v2.x starts at v2.4.0. [CHANGELOG.md](../CHANGELOG.md) lists what v2.5.0 added; all of it is in v3.0.0.

## Artifacts and dependencies

v3.0.0 is one artifact. Keep the dependency on `hiddenlayer-java` and remove any on the other two:

| v2.x artifact | v3.0.0 |
|---|---|
| `com.hiddenlayer.api:hiddenlayer-java` | the whole SDK |
| `com.hiddenlayer.api:hiddenlayer-java-core` | removed; its classes are in `hiddenlayer-java` |
| `com.hiddenlayer.api:hiddenlayer-java-client-okhttp` | removed; its classes are in `hiddenlayer-java` |

```kotlin
implementation("com.hiddenlayer.api:hiddenlayer-java:3.0.0")
```

The SDK's own code is Java where v2.x's was Kotlin, and its dependencies change:

- OkHttp moves from 4.12 to 5.2, and is part of the SDK's API: `httpClient` and `addInterceptor` take OkHttp types.
- Jackson is 2.18. v2.x could run against Jackson back to 2.13.4; `checkJacksonVersionCompatibility` and `jsonMapper` are gone.
- `jackson-module-kotlin` is no longer a dependency. The Kotlin standard library still arrives with OkHttp.
- The ProGuard and R8 rules v2.x shipped inside `hiddenlayer-java-core` are not shipped. Models are (de)serialized through Jackson annotations, so keep `com.hiddenlayer.api.**` when you shrink.

Java 8 is still the minimum.

## Packages

| v2.x | v3.0.0 |
|---|---|
| `com.hiddenlayer.api.client.HiddenLayerClient` | `com.hiddenlayer.api.HiddenLayerClient` |
| `com.hiddenlayer.api.client.HiddenLayerClientAsync` | `com.hiddenlayer.api.AsyncHiddenLayerClient` |
| `com.hiddenlayer.api.client.okhttp.HiddenLayerOkHttpClient` | `com.hiddenlayer.api.HiddenLayerClientBuilder` |
| `com.hiddenlayer.api.client.okhttp.HiddenLayerOkHttpClientAsync` | `com.hiddenlayer.api.AsyncHiddenLayerClientBuilder` |
| `com.hiddenlayer.api.models.<resource>.*Params` | `com.hiddenlayer.api.resources.<resource>.requests.*`, or `com.hiddenlayer.api.types.*` for a request body that other types also use |
| `com.hiddenlayer.api.models.<resource>.*` (responses) | `com.hiddenlayer.api.types.*`, or `com.hiddenlayer.api.resources.<resource>.types.*` for a type only one resource uses |
| `com.hiddenlayer.api.services.blocking.*Service` | `com.hiddenlayer.api.resources.<resource>.*Client` |
| `com.hiddenlayer.api.services.async.*ServiceAsync` | `com.hiddenlayer.api.resources.<resource>.Async*Client` |
| `com.hiddenlayer.api.errors.*` | `com.hiddenlayer.api.core.HiddenLayerException`, `com.hiddenlayer.api.core.HiddenLayerApiException` and `com.hiddenlayer.api.errors.*` |

| `com.hiddenlayer.api.lib.*` | `com.hiddenlayer.api.lib.*`, see [the scanners](#model-and-community-scanners) |

A resource's directory is its name in lower case with no separators: `promptAnalyzer` is `resources.promptanalyzer`, and `evaluations.redTeam` is `resources.evaluations.redteam`.

`BaseHiddenLayerClient` and `AsyncBaseHiddenLayerClient` are the generated clients, without the scanners, the token from the environment or the beta warnings. Use `HiddenLayerClient` and `AsyncHiddenLayerClient`.

## Building a client

A client is built with `new HiddenLayerClientBuilder()`, which replaces both `HiddenLayerOkHttpClient.builder()` and `HiddenLayerOkHttpClient.fromEnv()`. The builder always reads the environment, and what you pass to it wins:

```java
// v2.x
HiddenLayerClient client = HiddenLayerOkHttpClient.fromEnv();

HiddenLayerClient client = HiddenLayerOkHttpClient.builder()
    .fromEnv()
    .prodEu()
    .timeout(Duration.ofSeconds(30))
    .build();

// v3.0.0
HiddenLayerClient client = new HiddenLayerClientBuilder().build();

HiddenLayerClient client = new HiddenLayerClientBuilder()
    .environment(Environment.PROD_EU)
    .timeout(30)
    .build();
```

`HiddenLayerClient.builder()` still compiles, but it is deprecated: it is the generated client's builder, and returns a `BaseHiddenLayerClient`.

| v2.x builder method | v3.0.0 |
|---|---|
| `fromEnv()` | none; the builder always reads the environment |
| `bearerToken(String)` | `token(String)` |
| `clientId(String)`, `clientSecret(String)` | unchanged |
| `baseUrl(String)` | `url(String)` |
| `prodEu()` | `environment(Environment.PROD_EU)`; `Environment.PROD_US` is the default |
| `timeout(Duration)` or `timeout(Timeout)` | `timeout(int)`, in seconds, for the whole call; the default is still 60 seconds |
| `maxRetries(int)` | unchanged; the default is still 2 |
| `putHeader(name, value)` and the other header methods | `addHeader(name, value)` |
| `putQueryParam(key, value)` and the other query methods | none; pass `addQueryParameter` in each call's [request options](#request-options) |
| `logLevel(LogLevel)` | `logging(LogConfig.builder().level(LogLevel.DEBUG).build())` |
| `proxy`, `proxyAuthenticator`, `sslSocketFactory`, `trustManager`, `hostnameVerifier`, `maxIdleConnections`, `keepAliveDuration`, `dispatcherExecutorService` | configure an `OkHttpClient` and pass it to `httpClient(OkHttpClient)` |
| `responseValidation(boolean)` | none; see [Responses](#responses) |
| `jsonMapper`, `checkJacksonVersionCompatibility`, `streamHandlerExecutor`, `sleeper`, `clock` | none |

Three options are new: `addInterceptor(okhttp3.Interceptor)`, `maxConcurrentRequests(int)` and the retry settings `retryOnStatusCodes`, `retryDelays`, `initialRetryDelayMillis`, `maxRetryDelayMillis` and `retryJitterFactor`.

`build()` throws an `IllegalStateException` when it has neither a token nor both a client ID and a client secret, from the builder or the environment. v2.x built the client and sent its requests without an `Authorization` header.

`client.withOptions(...)` is removed, on the client and on every service: build another client. `client.async()` is removed too; see [Asynchronous clients](#asynchronous-clients).

Requests send `User-Agent: com.hiddenlayer.api:hiddenlayer-java/3.0.0` (v2.x: `HiddenLayerClientImpl/Java 2.x`), unless a `User-Agent` header is set on the builder or the request, and the `X-Stainless-*` headers are gone.

## Environment variables

| Variable | v3.0.0 |
|---|---|
| `HIDDENLAYER_TOKEN` | read, unless `token`, or `clientId` and `clientSecret`, are passed |
| `HIDDENLAYER_CLIENT_ID`, `HIDDENLAYER_CLIENT_SECRET` | read: exchanged at `/oauth2/token` for a token that is reused until two minutes before it expires |
| `HIDDENLAYER_BASE_URL` | read, unless `environment` or `url` is called |
| `HIDDENLAYER_LOG` | no longer read; pass `logging` |
| `HIDDENLAYER_CUSTOM_HEADERS` | no longer read; call `addHeader` |

Credentials passed to the builder win over the environment: `token`, then `clientId` and `clientSecret`, then `HIDDENLAYER_TOKEN`, then `HIDDENLAYER_CLIENT_ID` and `HIDDENLAYER_CLIENT_SECRET`. A blank value counts as not set.

The system properties `hiddenlayer.token`, `hiddenlayer.clientId`, `hiddenlayer.clientSecret` and `hiddenlayer.baseUrl` are no longer read.

## Requests

A v2.x method took one `Params` object. In v3.0.0, path parameters are leading `String` arguments, and the body and query fields are in a request object:

```java
// v2.x
client.sensors().retrieve(SensorRetrieveParams.builder().sensorId(sensorId).build());
client.sensors().retrieve(sensorId);
client.scans().results().listFiles(
    ResultListFilesParams.builder().scanId(scanId).pageSize(100L).build());

// v3.0.0
client.sensors().retrieve(sensorId);
client.scans().results().listFiles(
    scanId, ListFilesResultsRequest.builder().pageSize(100).build());
```

Request and response builders are staged: each required field has to be set, in the order the builder offers them, before the optional ones and `build()`. A missing required field is a compile error where v2.x threw at `build()`.

```java
// v2.x
InteractionAnalyzeParams params = InteractionAnalyzeParams.builder()
    .metadata(InteractionAnalyzeParams.Metadata.builder()
        .model("gpt-5")
        .requesterId("user-1234")
        .build())
    .build();

// v3.0.0
InteractionsRequest request = InteractionsRequest.builder()
    .metadata(InteractionsMetadata.builder()
        .model("gpt-5")
        .requesterId("user-1234")
        .build())
    .build();
```

Nested request types are top-level classes named after the specification's schemas (`InteractionsMetadata`), where v2.x nested them in the `Params` class (`InteractionAnalyzeParams.Metadata`). Integers the specification doesn't mark as 64-bit are `int` and `Integer`, where v2.x used `Long`.

`toBuilder()` is replaced by `builder().from(existing)`. `putAdditionalHeader`, `putAdditionalQueryParam` and `putAdditionalBodyProperty` on a `Params` builder are replaced by [request options](#request-options).

## Responses

Getters are named `getX()` where v2.x named them `x()`. An optional field still returns an `Optional`:

```java
// v2.x
String scanId = report.scanId();
Optional<OffsetDateTime> endTime = report.endTime();

// v3.0.0
String scanId = report.getScanId();
Optional<OffsetDateTime> endTime = report.getEndTime();
```

Enums are classes with a constant per known value, as in v2.x, with other accessors:

| v2.x | v3.0.0 |
|---|---|
| `ScanReport.Status.DONE` | `Status.DONE`, a top-level class named after the specification's schema |
| `status.value()`, `status.known()` | `status.getEnumValue()`, which has a member for a value this version doesn't know |
| `status.asString()` | `status.toString()` |
| `Status.of("done")` | `Status.valueOf("done")` |

Removed from every model: the `_field()` accessors returning `JsonField`, `JsonValue`, `validate()` and `isValid()`. A property the SDK doesn't model is in `getAdditionalProperties()`. Responses are not validated beyond deserialization, as with v2.x's default, and `responseValidation` is gone.

`runtime.evaluateRequest` and `runtime.evaluateResponse` take and return the provider's payload as a `Map<String, Object>`, because the specification leaves it open.

## Pagination

Paginated methods return a `SyncPagingIterable<T>` in place of v2.x's `*Page` classes:

| v2.x | v3.0.0 |
|---|---|
| `page.autoPager()` | the `SyncPagingIterable` itself, an `Iterable<T>` over every item of every page; `streamItems()` for a `Stream<T>` |
| `page.items()` | `page.getItems()` |
| `page.hasNextPage()`, `page.nextPage()` | `page.hasNext()`, `page.nextPage()` |
| `page.response()` | `page.getResponse()`, an `Optional` of the response envelope |

```java
// v2.x
for (CardListResponse card : client.models().cards().list().autoPager()) { ... }

// v3.0.0
for (ModelCardV4 card : client.models().cards().list()) { ... }
```

Two methods change shape on purpose. In v2.x they returned the raw response envelope; in v3.0.0 they return a page of its items:

| Method | v2.x | v3.0.0 |
|---|---|---|
| `scans.jobs.list` (`GET /scan/v3/results`) | `JobListResponse`, with `items()` and `total()` | `SyncPagingIterable<ScanReportOfRecordV3Summary>`; the envelope is `page.getResponse()` |
| `sensors.query` (`POST /api/v2/sensors/query`) | `SensorQueryResponse`, with `results()` and `totalCount()` | `SyncPagingIterable<SensorSorItemResponse>`; the envelope is `page.getResponse()` |

## Asynchronous clients

`client.async()` is removed. Build an `AsyncHiddenLayerClient` with `new AsyncHiddenLayerClientBuilder()`, which takes the same options; its methods return `CompletableFuture`s, as v2.x's `HiddenLayerClientAsync` did.

```java
// v2.x
HiddenLayerClientAsync client = HiddenLayerOkHttpClientAsync.fromEnv();

// v3.0.0
AsyncHiddenLayerClient client = new AsyncHiddenLayerClientBuilder().build();
```

A paginated method of the asynchronous client completes with a `SyncPagingIterable`: the first page arrives without blocking, and iterating past it, or calling `nextPage()`, blocks the calling thread for each further page. v2.x's `*PageAsync` classes, `AsyncStreamResponse` and `autoPager().subscribe(...)` are removed.

Close an `AsyncHiddenLayerClient` when you are done with it. Its scanners run on threads of their own, which `close()` stops.

## Errors

| v2.x | v3.0.0 |
|---|---|
| `HiddenLayerException` (base) | `com.hiddenlayer.api.core.HiddenLayerException` (base) |
| `HiddenLayerServiceException`, with `statusCode()`, `headers()` and `body()` | `com.hiddenlayer.api.core.HiddenLayerApiException`, with `statusCode()`, `headers()` and `body()` |
| `BadRequestException` | `BadRequestError` |
| `UnauthorizedException` | `UnauthorizedError` |
| `PermissionDeniedException` | `ForbiddenError` |
| `NotFoundException` | `NotFoundError` |
| `UnprocessableEntityException` | `UnprocessableEntityError` |
| `RateLimitException`, `InternalServerException`, `UnexpectedStatusCodeException` | `HiddenLayerApiException`; check `statusCode()` |
| `HiddenLayerIoException`, `HiddenLayerRetryableException` | `HiddenLayerException`, with the `IOException` as its cause |
| `HiddenLayerInvalidDataException` | `HiddenLayerException`, when a response can't be deserialized |

The `*Error` classes are in `com.hiddenlayer.api.errors` and extend `HiddenLayerApiException`. A method throws the class for a status only where the specification declares that status for it; any other status is a plain `HiddenLayerApiException`. `body()` is the parsed response body as an `Object` (v2.x: a `JsonValue`).

```java
// v2.x
try {
    client.sensors().retrieve(sensorId);
} catch (NotFoundException e) { ... }

// v3.0.0
try {
    client.sensors().retrieve(sensorId);
} catch (HiddenLayerApiException e) {
    if (e.statusCode() == 404) { ... }
}
```

## Raw responses

`withRawResponse()` is on every resource client, as in v2.x. It is no longer on the client itself, and the response type changes:

```java
// v2.x
HttpResponseFor<SensorRetrieveResponse> response = client.sensors().withRawResponse().retrieve(sensorId);
int statusCode = response.statusCode();
Headers headers = response.headers();
SensorRetrieveResponse sensor = response.parse();

// v3.0.0
BaseHiddenLayerClientHttpResponse<SensorSorItemResponse> response =
    client.sensors().withRawResponse().retrieve(sensorId);
Map<String, List<String>> headers = response.headers();
SensorSorItemResponse sensor = response.body();
```

The raw response has no `statusCode()`: a raw method returns only for a 2xx status, and throws as the plain method does for any other.

## Request options

`RequestOptions` is still the last argument of every method, with these options:

| v2.x | v3.0.0 |
|---|---|
| `timeout(Duration)` or `timeout(Timeout)` | `timeout(Integer)`, in seconds, or `timeout(Integer, TimeUnit)` |
| `responseValidation(boolean)` | none |
| none | `maxRetries(Integer)` |
| `putAdditionalHeader` on the `Params` | `addHeader(String, String)` |
| `putAdditionalQueryParam` on the `Params` | `addQueryParameter(String, String)` |
| `putAdditionalBodyProperty` on the `Params` | `addBodyProperty(String, Object)` |

## Model and community scanners

`client.modelScanner()` (`scanFile`, `scanFolder`) and `client.communityScanner().communityScan` keep their arguments, their defaults and their behaviour, on both clients. The helpers are Java now, in the same package, `com.hiddenlayer.api.lib`. What changes:

- They return `ScanReportOfRecordV3`, the type that replaces `ScanReport`.
- `ScanFileOptions`, `ScanFolderOptions` and `CommunityScanOptions` keep their constructors, which take every argument, and their getters. Each gains a `builder()` that carries the defaults. Being Java classes, they have no `copy`, `componentN` or default arguments, which Kotlin callers of v2.x could use.
- The functions of `ScanUtils.kt`, which Java callers reached as `ScanUtilsKt.getScanResults` and so on, are static methods of `ScanUtils`: `getScanResults`, `waitForScanResults`, `getScanResultsAsync` and `waitForScanResultsAsync`. They take a `BaseHiddenLayerClient` or an `AsyncBaseHiddenLayerClient`, which the wrapper clients are.
- A path that doesn't exist, isn't a file or folder, or holds no file to scan throws an `IllegalArgumentException`, and a failed upload or scan throws a `HiddenLayerException` whose cause is the failure. v2.x threw a bare `RuntimeException` for both, with the same messages; both classes extend it.
- A failed part upload no longer puts the part's presigned URL, with its signature, in the exception message. The message names the URL without its query string.
- A scan that runs longer than about 25 minutes no longer fails with `timeout value is negative`: the delay between polls stays at its 30-second cap.
- `AsyncModelScanner` reads and uploads at most ten parts at a time, where v2.x could hold every part of a file in memory at once.
- The asynchronous scans retry a scan that isn't found yet when reading its file results too, as the synchronous ones did, and fail their future instead of leaving it pending when the scanner is closed mid-scan.
- A file larger than 2,147,483,647 bytes is refused before it is uploaded, with a `HiddenLayerException` that says so. The specification types the upload's content length as a 32-bit integer; v2.x sent it as a `Long`.
- The default ignore patterns of a folder scan are public, as `ScanFolderOptions.DEFAULT_IGNORE_FILE_PATTERNS`.

## Beta warnings

Calling a beta endpoint still logs one warning per endpoint per JVM, at `WARNING`, through the `java.util.logging` logger named `com.hiddenlayer.api.lib.BetaWarning`. The warning names the endpoint by HTTP method and path rather than by method name:

```
[BETA] POST /evaluations/v1/red-team: This endpoint is not GA or Production ready and is subject to changes at any time. Breaking changes may occur.
```

`BetaWarning.warnBeta(name)` stays. `BetaWarning.checkBetaEndpoint` takes the HTTP method before the path segments. The warnings come from an OkHttp interceptor the client builders add, so a client built with `BaseHiddenLayerClient.builder()` logs none.

## Removed

- `HiddenLayerOkHttpClient` and `HiddenLayerOkHttpClientAsync`, `client.async()`, `client.withOptions()` and `client.withRawResponse()`, covered above.
- The `hiddenlayer.*` system properties, `HIDDENLAYER_LOG` and `HIDDENLAYER_CUSTOM_HEADERS`, covered above.
- `JsonField`, `JsonValue`, `JsonMissing` and the `_field()` accessors, `validate()`, `isValid()` and `toBuilder()`.
- `HttpClient`, `HttpRequest`, `HttpResponse` and the other `com.hiddenlayer.api.core.http` types, with the "completely custom HTTP client" they allowed. v3.0.0 always sends through OkHttp.
- `BetaEndpoints`, the registry of beta endpoints. v3.0.0 reads the list from a classpath resource and doesn't expose it.
- The ProGuard and R8 rules, and `checkJacksonVersionCompatibility`.

## New APIs

v3.0.0 covers every public operation in the specification, 207 in all, against 29 in v2.5.0, including access (API keys, permissions, tokens, users), asset inventory, audit, compliance, governance, integrations, metrics, MITRE ATLAS, model intelligence, prompt sets, scan indices, SSO integrations, supply chain and triage. [reference.md](../reference.md) lists each method.

## Migration checklist

- [ ] Depend on `com.hiddenlayer.api:hiddenlayer-java:3.0.0` alone; remove `hiddenlayer-java-core` and `hiddenlayer-java-client-okhttp`.
- [ ] Check your own use of OkHttp against OkHttp 5.
- [ ] Replace `HiddenLayerOkHttpClient.fromEnv()` and `.builder()` with `new HiddenLayerClientBuilder()`, and `bearerToken`, `baseUrl` and `prodEu()` with `token`, `url` and `environment(Environment.PROD_EU)`.
- [ ] Replace `client.async()` with an `AsyncHiddenLayerClient`, and close it.
- [ ] Update imports from `com.hiddenlayer.api.client`, `.models` and `.services` to the [new packages](#packages).
- [ ] Pass path parameters as arguments, and replace each `Params` class with its request class.
- [ ] Rename response getters from `x()` to `getX()`.
- [ ] Iterate `scans.jobs.list` and `sensors.query` as pages, or read `page.getResponse()`.
- [ ] Replace `page.autoPager()` with the page itself, and `page.items()` with `page.getItems()`.
- [ ] Catch `HiddenLayerApiException` and its `*Error` subclasses in place of `HiddenLayerServiceException` and its `*Exception` subclasses.
- [ ] Replace `ScanUtilsKt.*` with `ScanUtils.*`, and `ScanReport` with `ScanReportOfRecordV3`.
